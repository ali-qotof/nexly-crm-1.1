# تقرير PHASE 10 — Frontend + Mobile UX

## الحالة: ✅ مبنية ومُجتازة للفحص الآلي — ⚠️ لم تُختبر بصريًا على متصفح/جهاز حقيقي

## 1. ما تم بناؤه (React 18 + TypeScript strict + Vite + Tailwind + TanStack Query)
- **RTL عربي من الأساس** (`dir="rtl"`، خط Cairo)، تصميم **موبايل أولًا**: شريط تنقل سفلي، أزرار
  بارتفاع 48px، Bottom Sheet للنوافذ على الموبايل ونافذة مركزية على الديسكتوب، دعم safe-area.
- **Boot Sequence** (`AuthContext`): فحص الجلسة → تجديد إن لزم → جاهز، وكل طلب له **timeout**
  وإلغاء. أي فشل شبكة ينتقل لشاشة "تعذر الاتصال بالخادم" + زر **إعادة المحاولة** — لا Splash أبدي،
  ولا `setTimeout` لإصلاح منطق، ولا MutationObserver.
- **عميل API مركزي**: timeout افتراضي 10 ث، أخطاء مهيكلة برسائل عربية (403/404/409/422/429/500)،
  محاولة تجديد جلسة **مرة واحدة** عند 401 دون حلقات.
- **الشاشات**: دخول، الرئيسية (لوحة المدير / مساحة عمل الموظفة مع Progress حقيقي)، عملائي
  (بحث بـ debounce، Pagination، أزرار اتصال/واتساب/متابعة/أوردر كبيرة)، تفاصيل العميل
  (بيانات + أوردرات + Timeline)، المتابعات (متأخرة/اليوم/قادمة)، الأوردرات، المنتجات والعروض،
  الموظفات (إضافة ← يُحوَّل مباشرة لشاشة التوزيع، تعطيل/تفعيل، حذف بكلمة مرور المدير)،
  التوزيع (اختيار موظفة، غير المخصصين/الكل، تحديد صفحة، إسناد/سحب، استيراد Excel بمعاينة
  Total/Matched/Missing/Duplicate/Invalid ثم تأكيد).
- **حالة كل شاشة**: Loading / Empty / Error+Retry. نظام Toast موحّد (لا `alert()`)، ولا Modal داخل Modal.
- **حماية الحفظ المزدوج**: نافذة الأوردر تولّد `idempotency_key` مرة واحدة عند الفتح، والزر
  يُعطَّل أثناء الحفظ، والإجمالي النهائي من الـ Backend (المعروض قبل الحفظ تقدير فقط).
- **ألوان الحالات** تُقرأ من `/settings/statuses` (مصدر واحد) وليست ثوابت في الواجهة.
- **PWA**: `manifest.webmanifest` فقط.

## 2. تغيير في الـ Backend اكتُشف احتياجه أثناء البناء
لم يكن هناك `GET /customers/{id}` رغم أن شاشة التفاصيل تحتاجه. أُضيف مع نفس فحص الصلاحية
المركزي (`ensure_customer_access`): 403 لموظفة غير مالكة، 404 لغير موجود، والمدير لأي عميل
(اختبار جديد → 62/62 اختبار backend).

## 4. حدود صريحة
- **لم أفتح الواجهة في متصفح حقيقي ولم أجرّبها على موبايل** — لا يوجد متصفح في بيئة التنفيذ.
  ما تحقق هو البناء والأنواع واختبارات منطق الـ API. **التحقق البصري/اللمسي (خصوصًا RTL، حجم
  الأهداف اللمسية، نافذة الأوردر على شاشة صغيرة) يجب أن تفعله أنت أو يُضاف Playwright في
  PHASE 11** — لن أدّعي أنه تم.
- لا تُوجد شاشات بعد لـ: إدارة المنتجات/الأسعار/العروض (CRUD من الواجهة)، إدارة التكاملات،
  الشكاوى، سجل التدقيق، التصدير (CSV/XLSX). الـ API جاهز لبعضها (منتجات، تكاملات، شكاوى)؛
  الواجهات ستُستكمل، والتصدير والتقارير لم يُبنَ backend له بعد — مسجَّل كفجوة أدناه.
- أيقونات PWA فارغة، وبلا Service Worker (لا offline فعلي).
- الأزرار نصية (لا مكتبة أيقونات) — قرار مقصود لتفادي أيقونات غير متناسقة/emoji.

## 5. فجوات مقابل قائمة "Definition of Done" (تُعالَج في PHASE 11)
Export (CSV/XLSX) — لم يُبنَ. `/health` لا يفحص قاعدة البيانات بعد. Rate limiter ما زال
in-process. تخزين المرفقات محلي. Retry الصادر للـ webhooks بلا Worker.
